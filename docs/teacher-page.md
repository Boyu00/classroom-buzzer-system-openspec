# 教師控制台（#15）

網址：啟動服務後開 `http://127.0.0.1:<port>/teacher.html`（首頁有入口）。頁面是原生 HTML／CSS／JavaScript 模組，沒有前端框架；操作都透過既有 API，即時狀態使用 A 的共用模組 `public/activity-stream.js` 的 `watchActivity`。

## 流程

1. **初次設定／登入**：尚未設定時顯示設定畫面（8～128 字元、需輸入兩次）；已設定則顯示登入。此瀏覽器若已是學生工作階段，會提示改用另一個瀏覽器或設定檔，並刻意不提供登出，避免該組無法重新加入。
2. **建立活動**：選速度或公平模式，產生六碼加入碼。重新整理頁面會透過 `GET /api/teacher/activity` 自動找回未結束（否則最近一場）的活動。
3. **匯入題目**（準備中）：貼上試算表網址或 ID → 讀取工作表 → 依勾選順序選擇（可上下移動，順序即掃描順序）→ 預覽（題數、單位數、每題原格位置）→ 確認匯入。解析失敗會逐項列出位置；失敗不會改動舊匯入。權限不足時提示要分享給哪個服務帳戶。
4. **開啟**：至少匯入一題才可開啟；開啟後鎖定模式與題目，匯入面板消失。
5. **監看**：各單位各組已送出的答案與受理順序、尚未送出的組別。速度模式標示暫定勝出者，公平模式顯示「勝出者：結束時計算」。只顯示已送出的內容，不追蹤草稿。
6. **結束**：需在確認對話框按「確認結束」。結束後顯示固定結果（最終順位、勝出、無人作答），可再建立新活動。

## 後端新增

`GET /api/teacher/activity`（教師限定）回 `{ data: { activity: { activityId, mode, state } | null } }`，不含加入碼等其他欄位。

## 安全與無障礙

- 伺服器 CSP 禁止內嵌腳本與樣式，所以頁面全是外部檔案；所有組名、答案與試算表內容經 `el()`／`mount()` 以文字節點加入，不使用 `innerHTML`。`tests/teacher-page.test.js` 會掃描禁止的寫法（含內嵌腳本、內嵌樣式、`innerHTML`、`eval`）。
- 表單有標籤、結果與錯誤以 `role=alert`／`role=status` 宣告、對話框為原生 `<dialog>`、按鈕與表格皆可鍵盤操作、有「跳到主要內容」連結。
- 變更請求帶 `X-CSRF-Token`，登入／登出後的新 token 會立即替換。

## 驗證

- `npm test`：含 `tests/teacher-page.test.js`（純邏輯、API 包裝、靜態安全檢查、伺服器提供頁面與 CSP）與 `tests/teacher-activity.test.js`。
- `npm run e2e:teacher`：以真實 Chrome（headless，CDP）走完整流程並可用 `--shots <資料夾>` 截圖：設定密碼、建立活動、匯入、學生加入與送出（含 `<script>` 惡意字串）、即時監看、重新整理、結束確認、登出與重新登入。需要本機有 Chrome 或 Edge（可用 `CHROME_PATH` 指定）。結束後的連結檢查是「連結出現與否必須和端點是否存在一致」：只有 main 時為 32 項；疊上結果頁與 CSV 後為 34 項（另驗證結果頁連結指向正確活動、CSV 可下載且含 BOM）。這支腳本**以記憶體 Sheets 替身取代 Google**，不取代 AC-01／AC-03 的真實線上驗收，也不在 `npm test` 內執行。

## 已知限制

- 結束後本頁顯示簡單的結果表，並提供「查看結果頁」（#16）與「下載 CSV」（#19）連結。這兩個是獨立功能，連結以 `HEAD` 探測端點是否存在且型別正確，端點不存在時不顯示，所以不依賴它們的合併順序。寫回原 Sheets（#17）尚未完成。
- 結束後的快照沿用 results 格式，不含加入碼與組別清單，因此結束後無法列出「從未送出的組」。
- 真實 Google Sheets 的人工驗收與手機／螢幕閱讀器的實測尚未做。
