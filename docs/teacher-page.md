# 教師控制台（#15）

網址：啟動服務後開 `http://127.0.0.1:<port>/teacher.html`（首頁有入口）。頁面是原生 HTML／CSS／JavaScript 模組，沒有前端框架；操作都透過既有 API，即時狀態使用 A 的共用模組 `public/activity-stream.js` 的 `watchActivity`。

## 流程

1. **初次設定／登入**：尚未設定時顯示設定畫面（8～128 字元、需輸入兩次）；已設定則顯示登入。此瀏覽器若已是學生工作階段，會提示改用另一個瀏覽器或設定檔，並刻意不提供登出，避免該組無法重新加入。
2. **建立活動**：選速度或公平模式，產生六碼加入碼。重新整理頁面會透過 `GET /api/teacher/activity` 自動找回未結束（否則最近一場）的活動。
3. **匯入題目**（準備中）：貼上試算表網址或 ID → 讀取工作表 → 依勾選順序選擇（可上下移動，順序即掃描順序）→ 預覽（題數、單位數、每題原格位置）→ 確認匯入。解析失敗會逐項列出位置；失敗不會改動舊匯入。權限不足時提示要分享給哪個服務帳戶。
4. **開啟**：至少匯入一題才可開啟；開啟後鎖定模式與題目，匯入面板消失。
5. **監看**：各單位各組已送出的答案與受理順序、尚未送出的組別。速度模式標示暫定勝出者，公平模式顯示「勝出者：結束時計算」。只顯示已送出的內容，不追蹤草稿。
6. **結束**：需在確認對話框按「確認結束」。結束後顯示固定結果（最終順位、勝出、無人作答），可再建立新活動。

## 後端新增

`GET /api/teacher/activity`（教師限定）回 `{ data: { activity: { activityId, mode, state } | null } }`，不含加入碼等其他欄位。

## 安全與無障礙

- 伺服器 CSP 禁止內嵌腳本與樣式，所以頁面全是外部檔案；所有組名、答案與試算表內容經 `el()`／`mount()` 以文字節點加入，不使用 `innerHTML`。`tests/teacher-page.test.js` 會掃描禁止的寫法（含內嵌腳本、內嵌樣式、`innerHTML`、`eval`）。
- 表單有標籤、結果與錯誤以 `role=alert`／`role=status` 宣告、對話框為原生 `<dialog>`、按鈕與表格皆可鍵盤操作、有「跳到主要內容」連結。
- 變更請求帶 `X-CSRF-Token`，登入／登出後的新 token 會立即替換。

## 驗證

- `npm test`：含 `tests/teacher-page.test.js`（純邏輯、API 包裝、靜態安全檢查、伺服器提供頁面與 CSP）與 `tests/teacher-activity.test.js`。
- `npm run e2e:teacher`：以真實 Chrome（headless，CDP）走完整流程並可用 `--shots <資料夾>` 截圖：設定密碼、建立活動、匯入、學生加入與送出（含 `<script>` 惡意字串）、即時監看、重新整理、結束確認、登出與重新登入。需要本機有 Chrome 或 Edge（可用 `CHROME_PATH` 指定）。結束後的連結檢查是「連結出現與否必須和端點是否存在一致」：只有 main 時為 32 項；疊上結果頁與 CSV 後為 34 項（另驗證結果頁連結指向正確活動、CSV 可下載且含 BOM）。這支腳本**以記憶體 Sheets 替身取代 Google**，不取代 AC-01／AC-03 的真實線上驗收，也不在 `npm test` 內執行。

## 已知限制

- 結束後本頁顯示簡單的結果表，並提供「查看結果頁」（#16）與「下載 CSV」（#19）連結。這兩個是獨立功能，連結以 `HEAD` 探測端點是否存在且型別正確，端點不存在時不顯示，所以不依賴它們的合併順序。寫回原 Sheets（#17）尚未完成。
- 結束後的快照沿用 results 格式，不含加入碼與組別清單，因此結束後無法列出「從未送出的組」。
- 真實 Google Sheets 的人工驗收與手機／螢幕閱讀器的實測尚未做。

## 寫回原 Google Sheets 面板（#17／#18）

活動 CLOSED 後，教師頁在結果下方顯示「寫回原 Google Sheets」面板；API 與流程見 [writeback.md](writeback.md)。

1. **預覽寫回**：重讀線上 Sheets，列出各單位勝出組、要寫入的答案（純文字顯示）、目標格與狀態（將寫入／先前已寫入／無人作答不變更／衝突）。結構或原格內容與匯入時不同時，明示無法寫回並提示恢復原內容或另建活動重新匯入。
2. **確認暫停編輯**：必須勾選「已請其他人暫停編輯」，且預覽沒有衝突，才能按「寫回 Google Sheets」。
3. **結果如實呈現**：只有全部逐格回讀核對才顯示成功；失敗（確認未寫入）、待核對（不確定是否已寫入）、衝突各有顏色、文字與處理建議，並列出逐題實況；部分失敗顯示「x / y 格已核對成功」，不會顯示成功。
4. **重試**：上次未完成時按鈕改為「重試寫回」（需重新預覽並確認）；系統先回讀，已確認寫入的不會重複寫入，外部改成不同內容則停止。
5. **匯出紀錄**：超過一次時以可展開表格列出歷次狀態；重新整理頁面後仍會載入。

驗證：`npm test`（含 `model.js` 寫回純函式測試）與 `npm run e2e:teacher`（真實 Chrome）。E2E 使用有狀態的記憶體 Sheets 替身，涵蓋預覽、未確認不可寫、寫入逾時未套用（失敗）、逾時且讀不回（待核對）、讀取恢復後重試（不重複寫入）、原格被改（衝突，按鈕停用）、歷史紀錄與惡意字串純文字顯示。**不代表真實 Google Sheets 的 UI 驗收。**

## 快照順序與過期回應（review #37）

教師頁同時有 SSE（即時）與操作後的 HTTP 快照（保險）兩個來源，回應順序不保證。規則：

- 每次切換活動、登出或重新登入都會遞增「世代」，舊世代的 SSE 或 HTTP 回應一律丟棄。
- HTTP 快照請求期間若已收到 SSE 快照，丟棄該 HTTP 回應（SSE 每次狀態變更都會推送，不會漏掉較新的狀態）。
- 同一活動的階段只前進（PREPARING → OPEN → CLOSED）；較舊階段的快照（`model.isStaleSnapshot`）一律丟棄。

驗證：`tests/teacher-page.test.js` 測階段順序；`npm run e2e:teacher` 以 Chrome DevTools 的 Fetch 網域在回應階段攔住 `/snapshot`，重現兩個順序：① CLOSED 的 SSE 先到、舊 OPEN 的 HTTP 後到，畫面維持「已結束」；② 舊活動的 HTTP 回應在切換到新活動後才到，畫面維持新活動。把修正拿掉後這兩項都會失敗。上述規則集中在 `public/teacher/snapshot-gate.js`（純邏輯，不碰 DOM），`tests/teacher-page.test.js` 以固定測試涵蓋：CLOSED 的 SSE 先到、舊 OPEN 的 HTTP 後到；切換活動後舊 HTTP／SSE 回應丟棄；登出後舊回應不恢復快照，重新登入同一活動也不接受登出前的請求；同階段較新的 SSE 內容不被延遲的 HTTP 蓋回；SSE 中斷時 HTTP 保險仍有效。拿掉世代、SSE 序號或階段檢查任一項，對應測試都會失敗。

## 寫回面板的活動綁定與提示文案（review #40）

寫回面板的狀態與請求流程在 `public/teacher/export-controller.js`（純邏輯，不碰 DOM），`main.js` 只負責畫面：

- 每個請求（預覽、載入紀錄、寫回）送出前擷取「活動＋畫面世代」（`gate.current()`），回應、錯誤、finally 更新狀態前都比對 `gate.same()`；切換活動、登出、重新登入後抵達的舊回覆一律丟棄，不更新畫面、不顯示錯誤、不顯示成功提示。
- 同一種操作只接受最後一次請求的回覆（序號），連點造成的舊預覽不會蓋掉新預覽。
- **寫回一定使用預覽當下的活動**：預覽綁定 `previewScope`，寫回前再確認仍在同一個活動與世代，且預覽可寫回、老師已勾選暫停編輯，否則不送出任何請求。
- 切換活動與登出時 `reset()`：清除預覽、暫停編輯確認、歷史與最近結果。

提示文案（`model.describeExport`）依**逐題狀態與錯誤碼**產生，不再只看批次狀態：
- 部分成功、部分失敗：說明部分格子已寫入並核對成功，其餘失敗，已成功的不會重複寫入。
- 寫入後才發現的衝突（`STRUCTURE_CHANGED_AFTER_WRITE`、`CHANGED_EXTERNALLY`）、含待核對或已成功格的衝突：說明部分格子可能已寫入，請依逐題紀錄核對。
- 只有在能確定時才說「沒有寫入任何格」：寫入前就停止的衝突，或全部格子都確認未寫入。

驗證：`tests/teacher-export.test.js`（16 項）以可控制回應順序的假 API 涵蓋延遲預覽、延遲歷史紀錄、延遲寫回回覆（成功與失敗）在切換活動或登出後才抵達、重新登入同一活動、連續預覽、預覽綁定原活動，以及各種提示文案；`npm run e2e:teacher` 另在真實 Chrome 檢查切換活動後面板不殘留（確認 `main.js` 確實接上 reset）。將控制器的範圍／序號檢查或提示分支拿掉，對應測試都會失敗。
